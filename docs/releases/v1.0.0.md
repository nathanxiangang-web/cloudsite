# CloudSite 1.0.0

Release date: 2026-10-30. This release closes the current development phase.
The project enters maintenance: no new feature development without a new explicit
request. Existing data, provider reservations and recovery records are preserved.

## Included capabilities

- Product accounts, login and role-protected consumer/admin surfaces.
- File library, document previews, browser-supported media playback, direct
  downloads and revocable single-file shares with optional access codes.
- Cloud download preparation, operation-count limits, durable admission and
  idempotent receipts. A file is READY only after canonical confirmation.
- Admin user management, task queries, share management, resource display-name
  and category editing, persisted operation audits and scoped diagnostic reads.
- The completed admin navigation, responsive layout and focus improvements
  from PR #181, plus the literal `&amp;` magnet-tail fix from PR #182.

## Module boundaries and compatibility

Consumer and admin presentation use existing protected HTTP contracts. Product
admission owns intent and quota; acquisition owns pure source preparation and
the existing worker stages; IndexCore owns physical truth. Providers remain behind
their existing ports. Resource display edits do not rename storage files.

The database remains Schema 20, with no new migration. Existing `PANTA_*` names,
Go module/import paths, Compose project/service names, private configuration and
storage identities intentionally retain their compatibility names. The old alpha
deployment filenames are not an instruction to move data or recreate volumes.

Known limits remain explicit: pending cancellation requires no Job; running or
uncertain provider work has no automatic cancellation/retry. Unsupported magnet
semantics fail closed. Provider configuration does not prove an authenticated
115 session. Media playback depends on browser support. AI and private UserSpace
work are deferred and are not part of this release.

## Distribution and verification

The GitHub release provides Linux amd64 `cloudsite` and `panta-db` binaries,
build provenance, per-binary checksums, and an archive checksum. Native runtime
dependencies such as CA certificates, Python and Poppler are supplied by the
existing deployment image. This archive contains no credentials or database data.

Release publication requires the exact merged-main commit's three CI jobs to
complete successfully. The tag is immutable and the release workflow verifies
the version, main ancestry and successful push CI before publishing artifacts.
Source integration, artifact publication and production deployment are separate
facts; production acceptance requires its own image, health and UI receipt.

## Production upgrade and rollback

Build the product image from the retained compatible runtime base, replace only
the product binary, and label it with this release's exact source revision and
version. Preserve `serve-product-acquisition` and the configured worker setting.
Do not alter unrelated IndexCore/OpenList/database/edge services.

Before cutover, verify the current Schema 20, no active claimed download, protected
backup and isolated restore, and preserve the current image/Compose configuration.
After cutover, verify image/binary hashes, health, public routes, role protection,
task/admission preservation and the real Chrome preparation flow without creating
a download. On failure, restore the previous compatible image and Compose while
retaining the current database. Never downgrade to Schema 16 or overwrite new data.
