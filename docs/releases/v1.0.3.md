## Migration and rollout

Append Schema21 product_library_snapshots only;0001..0020 remain byte-identical.
library_snapshots defaultsfalse and requires whole_root_library=true. For the
Owner-authorized deployment enable it only in the product config after upgrade
and actual-runtime-identity privilege preflight. Apply explicit minimal grants
from ../library-187/runtime-grants.sql as the relevant table owner if needed.
No PUBLIC wildcard, automatic grant or SECURITY DEFINER.

Before replacing the product: drain active claims, stop only the product, take a
complete custom-format backup plus schema/role/config/Compose receipts, restore
network-isolated PostgreSQL16 and verify all table digests, then rehearse20->21
and check runtime rights. Keep old image and tested recovery script. Use exact
PR/main CI and official fixed-tag checksummed binaries, never latest.

Same21 binary can disable the feature; old20 binaries reject21. Old-version
rollback must stop the product, restore the complete pre-upgrade database with
verified ownership/grants and previous config/Compose, then start the old image.
After new business writes that restore loses newer data, so retain post-failure
backup and require a separate recovery decision; never blindly restore online.
